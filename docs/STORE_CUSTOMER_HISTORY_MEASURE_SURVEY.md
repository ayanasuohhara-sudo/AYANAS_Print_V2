## 結論（推奨構成）

| 目的 | 推奨 | 理由 |
|------|------|------|
| 店舗個人の利用履歴 | **App96（個人顧客マスタ）＋既存 `pcm_order_history.js`** | 既に `personal_customer_id` で App16 履歴を詳細画面表示済み |

## 3. A550 店舗顧客の個人識別

```text
App8  A550（請求先・法人）
  └─ App16  customer_code = "A550"
        ├─ client_name / client_name_kana   … 表示名・検索補助
        └─ personal_customer_id (= P######) … 個人キー（App96 と同一）
              └─ App96 個人顧客マスタ（71件）
```

| 指標（本番実測） | 件数 |
|------------------|------|
| App16 A550 受注 | 134 |
| うち `personal_customer_id` あり | 64 |

| App96 個人マスタ | 71 |

## 7. 寸法を複数セット・過去も残す方法

既存活用優先の選択肢:

### A. 推奨: App96 に寸法サブテーブル（履歴行）

1行＝1回の採寸セット。例:

| 列 | 例 |
|----|-----|
| `measured_at` | 採寸日 |
| `kimono_type` / `manage_no` | 対象着物・受注紐付け（任意） |
| `mitake` / `yuki` / `sode` / … | 寸法値 |
| `is_current` | 現行セットフラグ |
| `note` | メモ |

- 過去行は削除せず残す（現行だけフラグ）
- 受注時は App16 から「現行寸法を参照」するJSは後日

### B. 第二候補: 寸法専用アプリ（新規）

- `personal_customer_id` で App96/16 と連携
- 採寸回数が多く権限分離したい場合向き
- **現状は App96 拡張で足りる可能性が高い**

### C. 非推奨: App16 に都度寸法を直書きのみ

- 履歴比較・「この人の最新寸法」が弱い
- 受注に紐づくスナップショットとしては併用可
