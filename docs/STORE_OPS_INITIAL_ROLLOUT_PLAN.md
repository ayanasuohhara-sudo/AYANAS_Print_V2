# 初期運用計画（店舗責任者＋指定スタッフ）

- **作成**: 2026-11-02（Asia/Tokyo）
- **目的**: 一般公開前に、少数の実取引だけで店舗フローを確認する
- **禁止**: everyone ACL 開放、実顧客データの一括更新、未承認の allowlist／権限拡大

---

## 1. 体制

| 役割 | アカウント（現状） | 操作範囲 |
|------|-------------------|----------|
| 管理者・監視 | `info@ayanas.co.jp` | 全確認、訂正、監視スクリプト |
| 指定スタッフ | `matsuura@ayanas.co.jp` | App97 入金、App92 引き取り |
| 店舗責任者 | `ayanas20126@gmail.com` | 同上＋現場判断（未収例外は原則使わない） |
| 一般スタッフ | （付与なし） | App97 不可。App92 引き取り不可 |

追加メンバーが必要な場合は **ユーザー単位で ACL／allowlist に追加**し、everyone は開けない。

---

## 2. 期間イメージ（承認後に開始）

カレンダー日数の見積はしない。フェーズ完了条件で進める。

### フェーズ A — ドライラン（実金銭なし）
- **条件**: 検証 PCM（`P000002` 等）のみ
- **内容**: マニュアル §1–9 を通しで1周（受注→印刷→納品書→在庫→入金→引き取り）
- **完了条件**: 操作者が迷わず完了／質問リストが閉じる

### フェーズ B — 少数実取引（承認後）
- **件数目安**: 1日あたり少数（例: 先払い1・当日会計1・未入金案内1）を責任者が指定
- **必須記録**: 管理番号、個人顧客ID、スマレジ取引番号、税込金額、App97 入金番号、delivery_status 前後
- **毎回**: スマレジ税込 ↔ App97 充当合計を突合（±1 円は記録して継続判断）
- **完了条件**: 連続して差異なし／訂正 Runbook を使わず完走、または訂正が手順どおりに閉じた

### フェーズ C — 一般公開判断（本計画の外）
- allowlist 拡大または店舗ロール化
- App97 ACL 見直し
- **別途承認必須**

---

## 3. 1件あたりの標準手順（フェーズ B）

1. App96 で顧客確認（なければ新規）
2. App16 受注 → 店舗受注表印刷
3. 受注時入金がある場合のみ App97 登録（スマレジ突合）
4. 作業完了後、App19 で納品書作成・印刷
5. App92 で「引き取り待ち在庫」に出ることを確認（工場経由なら到着後）
6. 残額があればスマレジ → App97 → 残額0
7. App92（または App97）でバーコード引き取り完了
8. App16 が納品済・在庫から消えたことを確認
9. 当日締め: App97「日次入金照合」＋ `node scripts/_app97_stage_ops_monitor.js`

---

## 4. 監視・停止条件

| トリガ | 行動 |
|--------|------|
| スマレジと App97 の金額差（説明不能） | **新規入金・引き取りを停止**し管理者へ |
| 二重入金／過剰充当の疑い | 停止。取消履歴を確認 |
| 法人受注への誤更新 | 停止。差分を戻し報告 |
| App97 everyone が true になっている | 直ちに Stage1 ACL に戻す |
| 8%／非課税商品の登場 | 公開・実取引を止め仕様追加 |

監視コマンド:

```bash
node scripts/_app97_stage_ops_monitor.js
SMAREGI_AMOUNT=<当日税込合計> node scripts/_app97_stage_ops_monitor.js YYYY-MM-DD
```
