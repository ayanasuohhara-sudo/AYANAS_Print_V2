# A550 店舗入金管理簡略化 — 現状調査報告（実装・本番未着手）

- **作成**: 2026-11-14（Asia/Tokyo）
- **依頼**: 店舗現場から A550 の kintone 入金再入力を廃止し、スマレジを売上正本・受注表の入金チェックのみにしたい
- **本報告の範囲**: **調査のみ**。実装・フィールド追加・本番反映は**承認後**
- **非変更（本調査中）**: App16/19/21/8/35/97 のデータ・ACL・本番 JS

## 0. 結論（先に）

| 結論 | 内容 |
|------|------|
| 店舗入金の正本アプリ | **App97「店舗入金管理」**（S1）。指示文の App21 ではない |
| App21 | **法人入金**（請求書 App35 充当）。A550 入金は設計上 0 件・使わない |
| App16 支払状況フィールド | **現状なし**。入金状態は App97 充当から都度計算 |
| 納品・引き取りゲート | App92/App97 が **App97 残額≤0（入金済）** を要求 |
| ダッシュボード | A550「受注金額」は App16 明細税抜。スマレジ売上は**未連携** → 二重計上の直接加算は現状なし。ただし運用上「kintone受注額＝店舗売上」と誤読するリスクあり |
| 改修方針案 | App16 に **未入金／一部入金／入金済** の3値を追加し、一覧で選択・絞り込み。App97／App21 新規登録は店舗オペから不要。法人 App21/35 は不変。**一部入金≠入金済**（納品・引き取り） |

**独立アプリ新設は不要。** 既存 App16＋ゲート改修＋メニュー／マニュアル更新で足りる。

## 1. 調査結果一覧

### 1.1 App16 の支払状況フィールド

| 項目 | 結果 |
|------|------|
| `payment_status`（未入金／入金済） | **App16 に存在しない** |
| フィールド辞書 | `payment_status` は **App35 請求書**（未入金／一部入金／入金済） |
| 現行の「入金状況」 | App97 の有効入金を `getOrderBalance` で集計し、印刷・引き取り UI に表示 |
| 初期値「未入金」 | App16 側フィールドがないため未定義。計算上は充当0＝未入金 |

**再利用候補**: App16 に同趣旨のフィールドが無いため、**新規追加が必要**（重複作成ではない）。  
App35 の `payment_status` は請求書用であり **App16 では再利用不可**（別アプリ・法人請求連携）。

案（承認後）:

| 項目 | 案 |
|------|-----|
| コード | `store_payment_status`（仮。実装時確定） |
| 型 | DROP_DOWN |
| 選択肢 | `未入金` / `一部入金` / `入金済` |
| 初期値 | `未入金` |
| ラベル表記 | 既存ゲート・印刷は **「入金済」**（「入金済み」ではない）。UI 文言は既存に合わせる |

PCM 反映直後バックアップ（36 フィールド）にも支払系コードは **0 件**（`payment*` なし）。

### 1.2 App21 の A550 入金登録

| 項目 | 結果 |
|------|------|
| App21 役割 | 法人入金 V2（`payment_create.js` → App35 請求充当） |
| A550 利用 | 設計書どおり **A550 入金 0 件・店舗会計に使わない** |
| 店舗入金 | **App97**（`STORE_PAYMENT_APP_ID = 97`） |

→ 指示の「App21 への A550 入金登録を不要」は **現状すでに実質不要**。廃止対象のオペは **App97 への手入力**。

### 1.3 App19 の A550 納品時の支払確認

| 経路 | 支払確認 |
|------|----------|
| App19 納品書作成＋`delivery_complete_sync` | A550 は App16 へ `delivery_status` / `delivery_no` / `delivery_date` 同期。**入金額の再入力はしない** |
| App92 バーコード引き取り | **`requirePaid` 既定 true** → App97 残高で未入金／一部入金を拒否（App97 へ誘導） |
| App97 内引き取り | 同一共有ゲート（`store_pickup_shared`） |

**未入金の既存仕様（報告）**

1. 残額 > 0 かつ未収入金引き渡し承認なし → 引き取り不可（メッセージで App97 案内）
2. 一部入金も原則不可（管理者の `unpaid_handover_approved` 例外のみ）
3. 先払い（残額 0）→ 再入金不要で引き取り可

簡略化後の期待: **App16「入金済み」チェック＝先払い相当**とし、ゲートを App97 残額計算から切替／併用する必要あり。

### 1.4 店舗受注一覧の JavaScript

| 項目 | 結果 |
|------|------|
| App16 一覧で入金トグル | **未実装** |
| 関連 JS | `order_pcm_*` / `order_customer_search` / 印刷プラグイン等。支払フラグ編集なし |
| 印刷 | `js/store_print_payment.js` が App97 から状態取得して印字 |

一覧上のチェック切替は **新規 JS**（`app.record.index.edit.show` 等、またはカスタム一覧 UI）が必要。

### 1.5 A550 売上集計・ダッシュボード

| 集計 | ソース | スマレジ |
|------|--------|----------|
| App82 業務ダッシュボード「ayanas店舗 A550」受注金額 | App16 `detail_table.amount`（税抜・登録済み分） | 未参照 |
| App82 ④お金（売掛・入金） | App35 / App21（法人） | 未参照 |
| App87 店舗ポータル「本日の店舗入金額」 | **App97** 当日有効入金合計 | 未参照 |
| App35 法人請求・売掛 | 法人のみ | 対象外（変更禁止） |

**二重計上**: コード上、スマレジ金額を kintone 売上に加算する経路は**無い**。  
リスクは運用・帳票解釈側（kintone 受注額とスマレジ売上を足す／併記する）。簡略化後はダッシュボード注記と App87「本日入金額」KPI の扱いを決める必要がある。

### 1.6 既存の支払状況更新処理との競合

| 処理 | 競合の有無 |
|------|------------|
| App97 `registerPayment` → 残額計算 | App16 にフラグを置く場合、**どちらを正とするか**を決めないと二重正本になる |
| 印刷 `getOrderBalance` | App97 依存。フラグ優先に変えると印刷表示も追随要 |
| 引き取りゲート | 同上 |
| App21 / App35 同期 | A550 非対象 → **競合なし**（維持） |

推奨: 簡略化後の A550 正本は **App16 の2値フラグ**。App97 は履歴参照のみ（新規登録 UI を店舗から外す）。過去 App97 データは削除しない。

### 1.7 複数着をまとめて支払う場合

| 現状（App97） | 1 入金レコードに複数 `store_payment_lines`（受注＝manage_no 単位充当） |
| 簡略化後案 | 着ごとに App16 フラグを個別 ON。まとめ会計はスマレジ側。kintone は「何着入金済みか」のチェックのみ |
| 注意 | 一括で複数レコードを一覧からまとめて「入金済み」にする UI は任意（承認時に要否） |

## 4. 未入金のまま納品する現行仕様（詳細）

1. **通常**: 未入金／一部入金 → App92/97 引き取り完了不可。  
2. **例外**: App97 `unpaid_handover_approved`（未収入金引き渡し承認）時のみ残額>0 で完了可（管理者向け・通常運用非推奨）。  
3. **App19 納品書作成自体**は支払チェックを強制しない（納品書番号付与・同期は可能）。支払ゲートは主に**引き取り完了**時点。

簡略化後も「未入金チェックのまま引き渡すか」は運用判断が必要（現状の管理者例外を残すか廃止するか）。

## 6. 改修方針（3状態・追記 2026-11-14）

### 6.1 入金状況（kintone のみ）

| 値 | 意味 | App21/App97 登録 |
|----|------|------------------|
| **未入金**（初期値） | スマレジ未会計または未確認 | 不要 |
| **一部入金** | 内金・分割など（金額はスマレジ） | 不要 |
| **入金済** | 完済（金額・日付はスマレジ） | 不要 |

- 金額・入金日・決済手段は **スマレジ正本**。kintone は状況ラベルのみ。
- **一部入金を選んでも App21 入金登録は不要**（法人フロー非介入）。
- App97 新規手入力も店舗オペから外す（履歴削除なし）。

### 6.2 App16 店舗受注一覧

| 要件 | 方針 |
|------|------|
| 選択・変更 | 一覧上で DROP_DOWN を直接変更（詳細を開かない）。`app.record.index.edit.show` 系またはカスタム列 |
| 絞り込み | 一覧ビュー／クエリで `store_payment_status in ("未入金")` 等。標準絞り込み＋必要ならクイックフィルタ UI |
| 対象行 | `customer_code = A550` のみ編集可（法人行は非表示または読取専用） |

### 6.3 納品・引き取り（App19 / App92）

| 状況 | 判定 |
|------|------|
| 入金済 | 支払完了としてゲート通過可（先払い相当） |
| **一部入金** | **入金済とみなさない**（現行 App97 計算と同じ） |
| 未入金 | 入金済とみなさない |

App19 納品書作成自体の支払強制は現状弱いが、**引き取り完了ゲート**では一部入金を拒否するよう明示改修する。

### 6.4 非変更

- 法人顧客入金、**App21**、**App35**、App8
- 過去 App97 データの削除なし

### 6.5 改修対象ファイル（案・未実装）
