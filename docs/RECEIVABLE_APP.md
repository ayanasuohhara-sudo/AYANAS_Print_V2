# 売掛一覧アプリ Version 1.0

請求書作成アプリ（App 35）・入金管理アプリ（App 36）の情報から、売掛残高を読み取り専用で一覧表示する。

V1.0 では売掛一覧アプリからのデータ更新は行いません。

---

## アプリ構成

| アプリ | App ID | 役割 |
|--------|--------|------|
| 請求書作成 | 35 | 請求・売掛データの取得元 |
| 入金管理 | 36 | 今月回収額の取得元 |
| 売掛一覧 | **37** | 読み取り専用ダッシュボード |

App ID は `js/receivable_create.js` の定数で変更可能。

---

## フォーム構成（参照用）

V1.0 ではレコード手入力は不可。以下は表示項目のフィールド定義です。

### キー項目

| フィールド名 | フィールドコード |
|-------------|----------------|
| 請求先コード | customer_code |
| 請求先名 | customer_name |
| 請求番号 | invoice_no |

### 表示項目

| フィールド名 | フィールドコード | 取得元 |
|-------------|----------------|--------|
| 請求日 | invoice_date | 請求書 |
| 支払期限 | due_date | 請求書 |
| 請求金額 | invoice_amount | 請求書 |
| 入金累計 | payment_total | 請求書（payment_amount） |
| 売掛残高 | accounts_receivable | 請求書 / 算出 |
| 回収状況 | collection_status | 請求書 / 算出 |
| 最終入金日 | last_payment_date | 請求書 |
| 経過日数 | elapsed_days | 請求書 / 算出 |
| 担当者 | in_charge | 請求明細（invoice_detail）先頭行 |

**回収状況:** 未回収 / 一部回収 / 回収済

---

## 一覧構成

プラグインが請求書・入金管理から取得したデータをカスタム一覧で表示します。

| 並び替え | 内容 |
|---------|------|
| 請求先別 | customer_code 昇順 → 請求日 降順 |
| 請求日順 | 請求日 降順 → 請求番号 昇順 |
| 売掛残高順 | 売掛残高 降順 → 請求日 降順 |
| 支払期限順 | 支払期限 昇順 → 請求番号 昇順 |

### 色分け

| 条件 | 色 |
|------|-----|
| 未回収 | 赤 |
| 一部回収 | オレンジ |
| 回収済 | 緑 |
| 期限超過 | 背景赤（回収済以外） |

---

## 集計内容（画面上部）

| 項目 | 内容 |
|------|------|
| 売掛総額 | 売掛残高の合計 |
| 未回収件数 | 回収状況 = 未回収 の件数 |
| 期限超過件数 | 支払期限超過かつ未回収/一部回収 の件数 |
| 今月回収額 | 入金管理アプリの当月 payment_amount 合計 |

---

## プラグインファイル

| ファイル | 内容 |
|----------|------|
| `js/receivable_create.js` | 請求書・入金データ取得・集計 |
| `js/receivable_index.js` | 読み取り専用一覧 UI |
| `css/receivable_index.css` | 一覧・色分けスタイル |

---

## テスト方法

1. App 37 を作成し、プラグインをインストール
2. 請求書（App 35）に確定済み請求データがあることを確認
3. 入金管理（App 36）に当月入金データがあることを確認
4. 売掛一覧アプリの一覧画面を開く
5. 集計・並び替え・色分けが正しいことを確認
6. レコード新規/編集がブロックされることを確認
