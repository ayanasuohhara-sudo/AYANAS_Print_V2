# A550 納品書訂正 — 管理者手順（v1）

- **作成**: 2026-11-01（Asia/Tokyo）
- **対象**: App19（納品書）↔ App16（受注）の A550 連携後の手修正
- **方針**: v1 は **自動巻き戻しなし**。編集画面で警告＋確認ダイアログのみ

---

## 1. 前提

| 項目 | 内容 |
|------|------|
| 同期タイミング | App19 保存成功後（`delivery_complete_sync.js`） |
| A550 反映内容 | `delivery_status=納品待ち`, `delivery_no`, `delivery_date` のみ |
| 触らない | `process_status` / `location_status` / `work_status` |
| 二重登録防止 | 既存 `delivery_no` が別番号なら **更新せず警告** |
| 納品済 | 既に `delivery_status=納品済` の受注は **スキップ**（App97 引き渡し後） |

---

## 2. よくある不整合

| 状況 | App19 | App16 | 症状 |
|------|-------|-------|------|
| 明細から行を削除して保存 | 行なし | 旧 `delivery_no` 残存 | スケジュール除外・納品待ち在庫に残る |
| 別管理番号に差し替え | 新番号 | 旧番号のまま | 同上＋新番号が未連携の可能性 |
| 納品書ごと削除 | レコードなし | 旧値残存 | 同上（削除ハンドラなし） |
| 納品書を作り直し | 新 `delivery_no` | 旧番号があるため warn | 新番号が載らない |

---

## 3. 訂正手順（管理者）

### 3.1 明細削除・差し替えで App16 を戻す場合

1. App19 で対象納品書の `delivery_no` と、外した `manage_no` を控える
2. App16 で当該 `manage_no` を開き、以下を確認する  
   - `delivery_status` / `delivery_no` / `delivery_date`  
   - `location_status`（店舗にあるか）  
   - `process_status`（完了か）
3. **納品書連携を取り消す**場合（スケジュールへ戻す）:  
   - `delivery_no` を空にする  
   - `delivery_date` を空にする（運用で残す場合は残してよい）  
   - `delivery_status` を運用方針に合わせて戻す  
     - 完了後・納品書前なら通常は `納品待ち` のまま、または `未納品`（App30 運用に合わせる）  
   - **process / location / work は変更しない**（本手順の対象外）
4. App92 を再読込し、  
   - スケジュールに再表示されること（`delivery_no` 空）  
   - 「納品待ち在庫」「店舗未到着」から消えること  
   を確認する

### 3.2 別納品書番号で再連携したい場合

1. App16 の既存 `delivery_no` を空にする（または正しい番号に手動で合わせる）
2. App19 の正しい納品書を再保存する（`edit.submit.success` で同期再実行）
3. 別番号が残ったまま再保存すると **warn でスキップ**される点に注意

### 3.3 納品書削除後

1. 削除前に明細 `manage_no` 一覧を控える（削除後は辿れない）
2. §3.1 と同様に App16 を手修正する
3. 必要なら正しい納品書を新規作成し直す

### 3.4 引き渡し済み（納品済）の扱い

- App97 で `delivery_status=納品済` になった受注は、納品書側の訂正では **自動では戻さない**
- 誤引き渡しの戻しは別運用（本 runbook 対象外）。戻す場合は App16 を管理者が直接訂正し、入金・在庫の影響を別途確認する
