# AYANAS 基幹システム Version 1.0 — 監査ログ（Audit Log）設計

## 1. 目的

重要な操作履歴を記録し、後から **誰が・いつ・何を・どう変更したか** を確認できるようにする。

- Version 1.0: **閲覧のみ**（データ復元機能は実装しない）
- 請求締め実行履歴（App 38）は一括請求専用。本設計は **全業務操作** を横断する汎用監査ログ

---

## 2. 監査ログアプリ構成

### 2.1 新規アプリ

| 項目 | 内容 |
|------|------|
| アプリ名 | 監査ログ |
| App ID（予定） | **39** |
| 役割 | 操作履歴の追記専用（プラグインから POST） |
| 主キー | `audit_id`（自動採番: `AUD-YYMMDD-001`） |
| ユーザー操作 | **閲覧のみ**（追加・編集・削除不可） |

### 2.2 フィールド定義

| 項目名 | フィールドコード | 型 | 説明 |
|--------|----------------|-----|------|
| 監査ID | audit_id | 文字列 | ログ1件の識別子 |
| 操作日時 | operated_at | 日時 | 操作実行日時 |
| ユーザー | operated_by | 文字列 | kintone ログインユーザー名 |
| ユーザーコード | operated_by_code | 文字列 | ログインコード（任意） |
| アプリID | app_id | 数値 | 対象 kintone App ID |
| アプリ名 | app_name | 文字列 | 受注明細 / 納品管理 等 |
| レコード番号 | record_id | 数値 | kintone レコード ID |
| 業務キー | business_key | 文字列 | manage_no / delivery_no / invoice_no / payment_no |
| 操作内容 | action | ドロップダウン | 下記「操作種別」 |
| 操作概要 | action_summary | 文字列（1行） | 人が読める要約 |
| 変更前 | before_data | 文字列（複数行） | JSON（変更フィールドのみ） |
| 変更後 | after_data | 文字列（複数行） | JSON（変更フィールドのみ） |
| 関連請求番号 | related_invoice_no | 文字列 | 確定・入金等の横断参照用 |
| クライアント情報 | client_info | 文字列 | User-Agent 等（任意） |

### 2.3 操作種別（action）

| 値 | 説明 | 主な対象アプリ |
|----|------|--------------|
| 作成 | レコード新規保存 | 16, 19, 35, 36 |
| 編集 | レコード更新保存 | 16, 19, 35, 36 |
| 削除 | レコード削除 | 16, 19, 35, 36 |
| 請求確定 | 請求確定ボタン実行 | 35（連動: 19） |
| 請求取消 | 請求書取消実行 | 35（連動: 19） |
| 入金登録 | 入金レコード保存 | 36（連動: 35） |
| 入金取消 | 入金レコード削除/取消 | 36（連動: 35） |
| 印刷 | 帳票印刷実行 | 16, 19, 35 |

※ 売掛一覧（37）は V1.0 更新操作なし。印刷機能追加時のみ記録。

### 2.4 変更前 / 変更後の形式

```json
{
  "invoice_status": "作成中",
  "total": 110000,
  "payment_amount": 0
}
```

- **差分のみ** 記録（全フィールドのスナップショットは取らない）
- サイズ超過時は `action_summary` に要約し、JSON は主要項目に限定
- 印刷操作は `before_data` / `after_data` 空、`action_summary` に帳票種別を記録

## 3. プラグインモジュール（実装予定）

| ファイル | 役割 |
|----------|------|
| `js/audit_log.js` | ログ組み立て・POST・差分計算 |
| `js/audit_log_index.js` | 監査ログアプリ一覧 UI（新しい順・フィルタ） |
| `js/audit_log_hooks.js` | 各アプリイベントへのフック登録 |

### 3.1 公開 API（案）

```javascript
AuditLog.record({
  appId: 35,
  appName: '請求書作成',
  recordId: 123,
  businessKey: '2608-001',
  action: '請求確定',
  actionSummary: '請求確定: 2608-001（納品3件）',
  before: { invoice_status: '作成中' },
  after: { invoice_status: '確定' },
  relatedInvoiceNo: '2608-001',
});
```

## 4. 記録タイミング

| 操作 | トリガー | 記録タイミング | 対象 App |
|------|---------|--------------|---------|
| 作成 | `*.create.submit.success` | 保存成功直後 | 16, 19, 35, 36 |
| 編集 | `*.edit.submit.success` | 保存成功直後（作成中のみ等の業務チェック後） | 16, 19, 35, 36 |
| 削除 | `*.index.delete.submit` / 詳細削除 | 削除成功直後 | 16, 19, 35, 36 |
| 請求確定 | `InvoiceCreate.confirmInvoice` 成功後 | API 更新完了直後 | 35, 19（1ログに集約） |
| 請求取消 | `InvoiceCreate.voidInvoice` 成功後 | API 更新完了直後 | 35, 19 |
| 入金登録 | `payment_desktop` 保存成功後 | 請求書同期完了後 | 36, 35 |
| 入金取消 | 入金削除成功後 | 請求書同期完了後 | 36, 35 |
| 印刷 | `Preview.open` 実行時 | プレビュー表示直前 | 16, 19, 35 |

### 4.1 記録しない操作

- 売掛一覧（37）の画面表示・並び替え（読取のみ）
- 請求締め実行履歴（38）の閲覧
- 監査ログ自体の閲覧（V1.0）
- 未請求データ取込・一括作成の **途中状態**（完了時に38または監査ログへ1件）

### 4.2 請求確定・取消の記録例

**請求確定（1操作 = 1ログ）**

| 項目 | 内容 |
|------|------|
| app_name | 請求書作成 |
| business_key | 2608-001 |
| action | 請求確定 |
| before_data | `{"invoice_status":"作成中"}` |
| after_data | `{"invoice_status":"確定","delivery_count":3}` |
| action_summary | 請求確定: 2608-001 / 納品3件を請求済に更新 |

**入金登録**

| 項目 | 内容 |
|------|------|
| app_name | 入金管理 |
| business_key | PAY-2608-001 |
| related_invoice_no | 2608-001 |
| before_data | `{"payment_amount":0}` （請求書側） |
| after_data | `{"payment_amount":50000,"payment_status":"一部入金"}` |

## 5. 一覧 UI（V1.0）

監査ログアプリ（App 39）一覧にプラグイン UI を表示。

| 表示列 | フィールド |
|--------|-----------|
| 操作日時 | operated_at |
| ユーザー | operated_by |
| アプリ名 | app_name |
| 業務キー | business_key |
| 操作内容 | action |

- 並び順: **operated_at 降順**（新しい順）

- 詳細画面: `before_data` / `after_data` を整形表示

## 6. 権限

| グループ | 監査ログ App 39 |
|---------|----------------|
| 一般ユーザー | 閲覧不可 |
| 経理担当 | 閲覧可 |
| 管理者 | 閲覧可 |
| プラグイン | API 経由で **追加のみ**（編集・削除不可） |

kintone アプリ設定で「レコード追加 = システム（API）のみ」「閲覧 = 管理者・経理」の構成とする。

---

## 7. App 38（請求締め実行履歴）との関係

| 項目 | App 38 締め履歴 | App 39 監査ログ |
|------|----------------|----------------|
| 目的 | 一括請求バッチの結果 | 全操作の汎用監査 |
| 粒度 | バッチ1件 | 操作1件 |
| 参照 | 請求一覧下部 | 監査ログ専用アプリ |

一括作成完了時: App 38 にバッチサマリ、App 39 に `action=作成` を取引先件数分またはサマリ1件（V1.0 は **サマリ1件** を推奨）。
