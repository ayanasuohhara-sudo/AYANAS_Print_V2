## 6. 変更案（承認後の実施順）

### フェーズ 0 — 確認事項（承認者へ）

1. 「未着手」→「**未着**」でよいか（403 件の移行方針を含む）  
2. 「しみ抜き待ち」を廃止し「**しみ抜き中**」のみにする意図でよいか（待ちと作業中の区別をやめる）  
3. 既存「未着手」403 件は  
   - A: 選択肢変更と同時に「未着」へ一括移行（バックアップ必須）  
   - B: しばらく両方併存 → 移行後に「未着手」削除  
   - C: 選択肢だけ変え、データは手動運用で消化  
4. 併せて、現行 JS が書く **仕上げ待ち**（フィールド外）を「仕上げ中」等へ寄せる改修を同梱するか  

### フェーズ 1 — JS 先行（推奨）

1. `internal_ops_config.js` / `floor_portal_config.js` / `factory_inbound_config.js` / sorting・work UI 文言を新ラベルへ  
2. 単体テスト更新（`test_factory_*` / `test_store_work_*` / `test_complete_register_*` 等）  
3. 対象 App（30/84/87）へ **確認後** デプロイ  

### フェーズ 2 — App16 フィールド

1. バックアップ（フォーム fields JSON ＋ 必要なら `work_status` 利用レコード CSV）  
2. 選択肢を新 9 項目へ。default を **未着** に変更  
3. （承認された場合のみ）未着手→未着のレコード移行  

### フェーズ 3 — 検証

- App84: 未着の入庫・振り分け、しみ抜き中への更新が成功すること  
- App30: 仕上げ完了が従来どおり  
- App87: カード件数  
- App92 / S1: 回帰（delivery 系）  

---

## 7. リスクと注意

1. **未着手 403 件**を残したまま選択肢から消すと、一覧・編集で無効値表示・再保存時エラーの原因になる  
2. App84 が **しみ抜き中** を既に書こうとしているが、現行フィールドに無い → 追加はむしろ整合方向  
3. **仕上げ待ち** は本依頼に含まれないが、振り分け JS が非存在値を書いており、別チケット推奨  
4. S1・納期カレンダー・納品ステータスへの機能影響は小さい（work 非依存）
